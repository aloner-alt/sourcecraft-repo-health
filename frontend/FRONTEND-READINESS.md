# Готовность frontend

## Что работает локально

- Навигация, рейтинг: поиск, язык, сортировки, пагинация, пустой результат.
- Dashboard: шесть категорий, отдельное «Нет данных», независимое раскрытие
  колонок, факты, фильтры рекомендаций и переходы между фактами и действиями.
- Демо-анализ: очередь, сбор, расчёт, завершение, ошибка, остановка, повтор.
- Скачивание Markdown с явной пометкой демонстрационного отчёта.
- Мобильная навигация, Escape, видимый фокус, переход к содержимому,
  табличные цифры и уменьшение движения. Отдельные названия страниц.
- Общие loading/error/404 состояния. API-состояния потребуется проверить
  повторно после подключения реального источника.

## Что ещё нужно для полноценного продукта

- OpenAPI и backend URL: замена всех fixtures, проверка ответов и ошибок,
  реальные даты, источники и ссылки SourceCraft, поля репозитория.
- Я ID, защищённая сессия, права доступа; список своих репозиториев и добавление.
- Реальный запуск задачи, polling, защита повторного запуска на backend,
  восстановление задачи после обновления или ухода со страницы.
- Реальные Markdown/PDF отчёты и ошибки скачивания.
- Утверждённые формулы, пороги статусов, Data Coverage и Potential Score.
  Сейчас значения условные: категория fixtures не пересчитывается под каждый
  репозиторий, статус здоровья не следует утверждённым порогам.
- В рейтинге шесть примеров, не сто реальных проектов; активность сортируется
  по порядку fixture. Нужны реальные временные метки и данные рейтинга.
- Автоматизированные unit/E2E тесты и проверки приватности при интеграции.
  Текущая проверка — ESLint, TypeScript, сборка и ручные браузерные сценарии.

Не считать frontend-прототип готовым к production без этих зависимостей.

## Ограничение проверки экспорта

Кнопка локального Markdown реализована, однако встроенный браузер не
подтвердил событие сохранения файла. Нужна отдельная проверка скачивания
в обычном Chrome/Edge перед демонстрацией. PDF не имитируется.
