# Соответствие техническому заданию

Проверка выполнена по ТЗ «Yandex Cloud / SourceCraft Repo Health».

| Требование | Статус | Реализация |
|---|---|---|
| Repo Health Score 0–100 | Готово | Взвешенный расчёт с целочисленным отображением |
| Шесть категорий | Готово | Security, Activity, Documentation, CI/CD, Issues, Code Health |
| Объяснимость оценки | Готово | Метрики, формула, источник, evidence и Data Coverage |
| Отличать плохую оценку от отсутствия данных | Готово | `AVAILABLE`, `NO_DATA`, `PERMISSION_DENIED`, `COLLECTION_ERROR` |
| Приоритетные рекомендации | Готово | Priority, проблема, действие, обоснование, ожидаемый прирост |
| Публичный рейтинг | Готово | Сортировка и фильтры через API и `/ranking` |
| Я ID и «Мои репозитории» | Готово для public | Пользователь, рабочая область, импорт, первичный и повторный анализ |
| Периодический анализ | Готово | BullMQ Job Scheduler, настраиваемый интервал, retry/backoff |
| История Score | Готово | API истории и график на Dashboard |
| Экспорт отчёта | Готово | Markdown и PDF |
| Badge | Готово | Публичный SVG endpoint |
| Устойчивость к сбою источника | Готово | Изоляция коллекторов и продолжение расчёта по доступным данным |
| AppSec/SAST/SCA findings | Внешнее ограничение | Security не участвует в Score без реального AppSec-результата; файлы security hygiene не подменяют AppSec и отображаются только как зависимость методологии |
| Приватные/internal репозитории | Требует интеграции аккаунтов | Без проверяемой связи Я ID ↔ SourceCraft пользователь общий PAT не используется как доказательство доступа; такие импорты безопасно отклоняются |

## Критерий готовности демонстрации

Перед показом должны проходить backend tests, production build обоих приложений,
`/api/health/ready`, публичные страницы, скачивание отчётов и OAuth callback.
Пошаговый сценарий находится в [DEMO.md](DEMO.md).


## AppSec и подтверждение источника

Security не использует дерево файлов, lockfiles или самописный сканер. В текущем API-слое нет зафиксированного ответа AppSec findings, поэтому категория сохраняет `NO_DATA`; 401/403 и сетевые сбои показываются как `PERMISSION_DENIED`/`COLLECTION_ERROR`. Архив `sourcecraft-repo-health-security.zip` в рабочей среде не обнаружен и не использовался как подтверждение API.

Реализация поддерживает только явно настроенный `SOURCECRAFT_APPSEC_ENDPOINT`; это не заменяет подтверждение официальной формы API. До предоставления живого endpoint и ответа в рабочей среде Security остаётся `NO_DATA`.
