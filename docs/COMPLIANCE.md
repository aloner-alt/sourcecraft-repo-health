# Соответствие техническому заданию

Проверка выполнена по ТЗ «Yandex Cloud / SourceCraft Repo Health».

| Требование | Статус | Реализация |
|---|---|---|
| Repo Health Score 0–100 | Готово | Взвешенный расчёт с целочисленным отображением |
| Шесть категорий | Готово | Security, Activity, Documentation, CI/CD, Issues, Code Health |
| Объяснимость оценки | Готово | Dashboard раскрывает все метрики, исходные значения, веса, источники и evidence; формула и Data Coverage документированы |
| Отличать плохую оценку от отсутствия данных | Готово | `AVAILABLE`, `NO_DATA`, `PERMISSION_DENIED`, `COLLECTION_ERROR` |
| Приоритетные рекомендации | Готово | Priority, проблема, действие, обоснование, ожидаемый прирост |
| Публичный рейтинг | Готово | Глобальный `/repos`, реальное число SourceCraft likes, язык, активность, сортировка и фильтры через API и `/ranking` |
| Я ID и «Мои репозитории» | Готово для public | После Я ID сервис получает `/me/repos` для PAT стенда, импортирует публичные репозитории и поддерживает первичный/повторный анализ |
| Периодический анализ | Готово | Глобальное обновление каталога, BullMQ Job Scheduler, настраиваемый интервал, retry/backoff |
| История Score | Готово | API истории и график на Dashboard |
| Экспорт отчёта | Готово | Markdown и PDF |
| Badge | Готово | Публичный SVG endpoint |
| Устойчивость к сбою источника | Готово | Изоляция коллекторов и продолжение расчёта по доступным данным |
| AppSec/SAST/SCA findings | Готово при подключённом CLI | Реальные findings загружаются командой `src appsec defect list --json`; без CLI Security имеет `NO_DATA`, а не имитируемый балл |
| Приватные/internal репозитории | Требует интеграции аккаунтов | Без проверяемой связи Я ID ↔ SourceCraft пользователь общий PAT не используется как доказательство доступа; такие импорты безопасно отклоняются |
| Коммиты и полноценный bus factor | Необязательная часть | Activity использует contributors, MR, релизы и `last_updated`; для истории коммитов нужен отдельный проверенный API/CLI источник |
| Крупный репозиторий | Готово на границе файлов | Пагинация дерева и общий кэш проверены детерминированным тестом на 10 500 файлов (`pnpm test:large-repo`) |

## Критерий готовности демонстрации

Перед показом должны проходить backend tests, production build обоих приложений,
`/api/health/ready`, публичные страницы, скачивание отчётов и OAuth callback.
Пошаговый сценарий находится в [DEMO.md](DEMO.md).
