# Архитектура

## Поток данных

`SourceCraft API → Collectors → Scoring → Recommendations → PostgreSQL → API → Next.js`

NestJS принимает запросы, BullMQ сохраняет задания в Redis, worker параллельно запускает независимые коллекторы и сохраняет результаты в PostgreSQL. Ошибка одного источника превращается в `COLLECTION_ERROR` конкретной категории и не обнуляет остальные данные.

## Компоненты

- `SourceCraftClient` — REST API, таймауты, глобальный каталог `/repos`, пользовательский каталог `/me/repos` и пагинация.
- `RepositoryTreeProvider` — общий краткоживущий кеш дерева для трёх коллекторов.
- `AnalysisQueueService` — ручные задания, три попытки с exponential backoff и повторяющийся scheduler.
- `ScoringService` — взвешенная формула с перераспределением веса отсутствующих категорий.
- `RecommendationsService` — фактические рекомендации и Potential Score.
- Next.js — публичный рейтинг, Dashboard, история, Я ID и рабочая область.

## Масштабирование

API и workers не хранят локальное состояние и могут масштабироваться отдельно. Очередь исключает выполнение тяжёлого анализа внутри HTTP-запроса. Публичный каталог обходится стабильными страницами по 100 репозиториев; лимит одного sweep задаётся `SOURCECRAFT_CATALOG_MAX_PAGES`. Дерево обрабатывается до 50 000 элементов, issues и CI/CD — до 10 000 записей каждого типа. Для большего охвата увеличивается число worker-процессов, а не число API-инстансов.

## Доступ и приватность

Я ID создаёт локального пользователя. После входа `/me/repos` получает публичные репозитории, доступные SourceCraft PAT текущего стенда, и привязывает выбранные проекты к рабочей области. Только этот пользователь может вручную запускать повторный анализ. Публичные результаты доступны без входа.

Приватные и internal-репозитории отклоняются до появления проверяемой связки Я ID ↔ SourceCraft account/PAT. Это безопаснее, чем использовать общий сервисный PAT как доказательство прав пользователя.
