# Аудит соответствия ТЗ SourceCraft Repo Health

Дата сверки: 24 сентября 2026 года.

## Что реализовано в обязательной части

- Веб-сервис с воспроизводимым Docker Compose запуском.
- Repo Health Score 0-100 по шести категориям с явными весами.
- Перераспределение веса недоступных категорий и отдельный Data Coverage.
- Dashboard с итоговой оценкой, всеми метриками, исходными значениями, источниками, evidence, сильными/слабыми сторонами и рекомендациями.
- Конкретные приоритизированные рекомендации с ожидаемым влиянием на Score.
- Публичный рейтинг с языком, SourceCraft likes, последней активностью, фильтрацией и тремя сортировками.
- Обход глобального публичного каталога SourceCraft через `GET /repos` с пагинацией.
- Я ID, рабочая область, получение публичных репозиториев через `GET /me/repos`, первичный и повторный анализ.
- Периодический пересчёт через BullMQ, retry/backoff и изоляция отказов источников.
- Markdown- и PDF-отчёты, история Score и публичный SVG badge.

## Что улучшено после сверки

1. Каталог больше не ограничен списком организаций из env: используется глобальный SourceCraft endpoint.
2. Поле likes теперь заполняется реакцией `positive_low` из `repository.rating.reaction_counts`, а не постоянным нулём.
3. Activity учитывает четыре фактических сигнала: свежесть репозитория, contributors, merge requests за 90 дней и релизы.
4. Dashboard показывает все метрики и evidence категории, а не только первую запись.
5. После Я ID добавлена загрузка публичных репозиториев, доступных SourceCraft PAT стенда.
6. Security больше не подменяет AppSec проверкой наличия файлов: при подключённом актуальном SourceCraft CLI используются реальные findings, иначе категория получает `NO_DATA`.
7. Добавлен воспроизводимый тест пагинации и обработки дерева из 10 500 файлов.

## Ограничения, которые нельзя честно закрыть только кодом проекта

- AppSec/SAST/SCA: для заполнения категории на стенде нужен актуальный авторизованный SourceCraft CLI с командой `src appsec defect list`; опубликованный REST API отдельный endpoint findings не предоставляет.
- Приватные и internal репозитории: необходима проверяемая персональная связь пользователя Я ID с его SourceCraft identity/token. Общий PAT стенда не используется как доказательство прав.
- Коммитная история и точный bus factor: нужен подтверждённый Git/API/CLI источник с авторством и историей коммитов. Текущая Activity не имитирует эти данные.
- Финальная сдача также требует внешних артефактов: URL стенда, презентацию и видео демонстрации.

## Проверка перед демонстрацией

1. Запустить `pnpm test --runInBand` и `pnpm build` в backend.
2. Запустить `npm run lint` и `npm run build` во frontend.
3. Поднять `docker compose up -d --build`.
4. Проверить `/api/health/ready`, `/ranking`, Dashboard, Я ID, первичный и повторный анализ, Markdown/PDF.
5. На демонстрации отдельно показать категорию без данных: её вес исключается, а Score не падает автоматически.
