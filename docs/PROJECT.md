# Документация проекта

## О проекте

SourceCraft Repo Health помогает быстро оценить состояние репозитория. Сервис собирает доступные данные из SourceCraft, рассчитывает итоговый балл и объясняет, из чего он сложился. Это позволяет команде не разбирать вручную десятки настроек и файлов перед релизом или ревью проекта.

В анализ входят шесть направлений:

- документация;
- безопасность;
- CI/CD;
- активность разработки;
- работа с задачами;
- качество кода.

Если часть данных недоступна, сервис не ставит за неё ноль. Категория помечается как `NO_DATA`, `PERMISSION_DENIED` или `COLLECTION_ERROR`, а итоговый балл считается только по доступным данным. Рядом с оценкой показывается покрытие данных.

## Как устроен проект

- `frontend` — интерфейс на Next.js;
- `backend` — API на NestJS и TypeScript;
- PostgreSQL — репозитории, результаты анализа и история;
- Redis и BullMQ — очередь фоновых проверок;
- SourceCraft API и CLI — источник данных о репозиториях и AppSec;
- Docker Compose — локальный запуск всех компонентов.

Проверка запускается в фоне. Коллекторы независимо собирают данные, после чего backend рассчитывает баллы, сохраняет результат и формирует рекомендации. Ошибка одного источника не отменяет весь анализ.

## Запуск

Нужны Docker Desktop и Git.

1. Скопировать `backend/.env.example` в `backend/.env`.
2. Добавить в `backend/.env` токен SourceCraft и, при необходимости, параметры Яндекс OAuth.
3. Из корня проекта выполнить:

```bash
docker compose -p repo-health up -d --build
```

После запуска доступны:

- интерфейс — `http://localhost:3001`;
- API — `http://localhost:3000/api`;
- Swagger — `http://localhost:3000/docs`;
- проверка состояния — `http://localhost:3000/api/health/ready`.

Остановить проект можно командой:

```bash
docker compose -p repo-health down
```

Данные PostgreSQL и Redis сохраняются в Docker volumes.

## Настройки окружения

Основные параметры находятся в `backend/.env`:

| Переменная | Для чего нужна |
|---|---|
| `SOURCECRAFT_TOKEN` | доступ к SourceCraft API |
| `AUTH_JWT_SECRET` | подпись пользовательской сессии, строка от 32 символов |
| `YANDEX_CLIENT_ID` | идентификатор приложения Яндекс OAuth |
| `YANDEX_CLIENT_SECRET` | секрет приложения Яндекс OAuth |
| `YANDEX_CALLBACK_URL` | адрес возврата после входа |
| `SCHEDULE_ENABLED` | включает периодический анализ |
| `ANALYSIS_INTERVAL_HOURS` | интервал между проверками |

Секреты нельзя добавлять в Git. Файл `.env` уже исключён через `.gitignore`.

## Основные сценарии

На странице рейтинга можно выбрать публичный репозиторий и открыть его Dashboard. Там отображаются итоговый Score, оценки категорий, подтверждающие факты, история и рекомендации.

После входа через Яндекс пользователь получает свою рабочую область. В ней можно синхронизировать доступные репозитории и запустить повторный анализ. Готовый результат можно скачать в Markdown или PDF, а badge с оценкой — добавить в README репозитория.

## Расчёт оценки

Каждая категория получает балл от 0 до 100. Итоговая оценка — взвешенное среднее доступных категорий. Веса указаны в [методологии](METHODOLOGY.md).

`Potential Score` показывает, каким может стать результат после выполнения рекомендаций. Это ориентир: фактическая оценка определяется новым анализом.

## API

Полный список методов и схем доступен в Swagger. Основные запросы:

- `GET /api/repositories` — каталог репозиториев;
- `GET /api/repositories/:id` — Dashboard репозитория;
- `POST /api/repositories/:id/analyses` — запуск анализа;
- `GET /api/analyses/:id` — состояние и результат анализа;
- `GET /api/ranking` — публичный рейтинг;
- `GET /api/repositories/:id/history` — история оценок;
- `GET /api/analyses/:id/reports/report.pdf` — PDF-отчёт.

## Проверка перед сдачей

Backend:

```bash
cd backend
pnpm install
pnpm test
pnpm build
```

Frontend:

```bash
cd frontend
npm install
npm run lint
npm run build
```

## Ограничения

- AppSec работает только при наличии прав на SourceCraft AppSec. Если токен не имеет нужного разрешения, категория безопасности честно отображается как недоступная.
- Приватные репозитории не импортируются через общий сервисный токен.
- Частота коммитов пока не используется: для неё нужен отдельный надёжный источник Git history.
- Для публичного стенда нужны VM, домен и настроенный HTTPS. Готовая инструкция находится в [DEPLOY-YANDEX-CLOUD.md](DEPLOY-YANDEX-CLOUD.md).
